# 平台商品管理与工厂配置

商品库入口为 `/admin?screen=supplier-dbs`。工厂及成员统一在平台管理的“工厂管理”（`/admin?settings=supplier-accounts`）维护，使用真实 React 页面与现有商品、工厂、成员和授权接口。

## 单表管理

商品跨可访问工厂汇总到一张表，以商品库列标明归属。工具栏提供商品库、商品名称、类目、发布状态和待完善筛选。规格在同一张表中展开，不再使用左侧工厂列表和右侧商品页。

商品分组使用 `(sourceId, variantGroup)`；没有款号时按独立商品处理。不同工厂的相同款号不会合并。统计与分页按款计算，整组规格不会拆到不同页。跨工厂批量操作逐规格使用自身 `sourceId`，筛选或翻页后清除隐藏选择。

## 先配置工厂，再新增商品

1. 超级管理员在平台管理的“工厂管理”中新增工厂并填写首个登录邮箱。工厂账号由平台开通，不能自行注册；初始密码仅显示一次。
2. 工厂通过公开入口 `/supplier` 登录。尚未绑定商品库或授予履约权限时显示等待状态；管理员可在工厂下继续开通成员。
3. 在商品库页面选择“工厂绑定”，从已有工厂选择并填写商品库名称。已有未绑定的商品库也可补绑；一家工厂可绑定多本商品库。系统保留的 `src_unassigned` 用于未归属商品，不能在商品库页面绑定或删除。
4. 在对应商品库的“权限”中，从其工厂有效成员选择履约账号并绑定。每本商品库最多一个有效履约账号，只有超级管理员可绑定或解除。
5. 返回商品表格新增商品，选择已绑定工厂的商品库并填写首个规格名称。商品使用该商品库的 `sourceId`，新增商品不会隐式创建工厂。

履约绑定使用 `POST /api/admin/supplier-dbs/{source_id}/fulfillers`，请求为 `{ "account_uuid": "公开账号标识" }`，不再接收内部数字 `userId`。账号目录返回 `account_uuid`。后端校验账号存在、未停用且为工厂账号；保留每来源唯一有效履约授权及审计记录。解除绑定不删除历史授权和订单。绑定响应丢失时，界面显示待核实，管理员重新读取状态后再操作。

订单推单必须解析到该工厂的唯一有效履约授权；仅有商品归属或登录成员时不创建派发包。绑定完成后仍需满足委托、素材、物流等既有订单条件，不把“已绑定”作为完整推单就绪证明。

`sc_factories` 独立保存工厂资料，`sc_factory_members` 保存成员，`sc_sources.factory_id` 指向工厂。发布规格时，系统在同一事务中启用所属商品库的卖家可见性，无需单独设置；停用规格后该规格不再展示。已有已发布规格所属的商品库通过迁移启用可见性。

已有工厂的登录账号在成员列表中逐个管理。编辑工厂资料不提交登录邮箱，避免换绑时移除其他成员。

## 先命名，再填写三类资料

- 新增商品：先选择工厂并命名首个规格，再进入表单。
- 已有商品新增规格：先在命名弹窗填写规格名称，再创建规格并进入表单。取消命名不创建草稿，重名规格不会提交。创建失败保留名称；创建成功但读取失败时只重试读取，不重复创建。

新增与编辑统一为三个表单：平台商品信息 → Ozon 字段 → AI 识图。平台商品信息合并商品资料、规格、价格、素材、属性、包装与清单；不再单独设置“规格与素材”或“检查发布”步骤。第三步保存后返回商品表格。

表格在每条规格上独立显示 Ozon 与 AI 配置状态，点击状态可直接编辑该规格的对应表单。“新增规格”保留文字入口；发布与停用在表格中操作，原有就绪检查、缺项提示与权限限制继续生效。

新增规格默认复用现有 Ozon 类目与平台字段，并保留完整的可编辑页面。规格配置页仅保存当前规格的类目与 Ozon 字段，不覆盖其他规格。商品配置页仍提供整组共用配置，保存时会覆盖同步到同款规格；页面明确显示共用范围，类目更改需确认。共用字段通过现有逐规格接口串行同步；部分失败时明确提示重试，已保存内容保留，目前没有跨规格事务。规格的商品信息、实物包装参数、AI 商品事实、固定标签及识图填入开关各自保存。修改一个规格的 AI 事实不会同步覆盖其他规格。

Ozon 草稿可在 AI 步骤之前保存，固定标签暂时为空不阻止草稿写入。填写的标签仍校验格式、长度、重复和上限，发布时仍要求有效标签、商品事实、类目、平台价及有效 Ozon 配置。保存失败保留输入；未保存的 AI 配置离开前要求明确处理，失败的基础字段不能作为已保存内容继续。

“发布到平台商品库”只改变库内发布状态，不代表商品已发送到 Ozon 或已在售。非超级管理员不能通过归档、删除商品或删除工厂将已发布规格下架；需先由超级管理员停用。

## 权限

- 商品库上架、下架与平台供货价仅由超级管理员配置；同一限制覆盖单条、详情、批量与商品负责人接口。超级管理员维护全部工厂与商品负责人授权。
- 普通平台管理员只能维护服务端返回的自有工厂和获准商品资料，不能上架、下架或设置平台供货价；前端筛选不扩大授权。
- 商品负责人是工厂来源级授权，不是平台角色。可维护授权商品资料和供货成本；上架、下架与平台供货价仍只向超级管理员开放。原有 `/api/supplier-catalog` 来源隔离保留。
- 工厂成员读取其绑定的商品库目录，接单和发货仍需要独立履约授权。

商品负责人授权使用 `POST /api/admin/supplier-dbs/{source_id}/catalog-managers`，请求为 `{ "account_uuid": "公开账号标识" }`。服务端解析账号并校验账号用途，授权与撤销由超级管理员执行。历史授权记录保留。


## 商品负责人素材维护

获授权的平台账号通过侧栏“商品维护”（`/?screen=supplier-catalog`）维护本来源商品。入口依据账号概览的 `is_catalog_manager` 显示，真实读写仍逐次检查来源授权；撤销后目录读取、上传授权、确认与中止均返回 403。

已有商品的图集和 PSD 区在编辑页顶部。图集支持上传、封面选择、键盘/拖拽排序和删除；PSD 支持上传、下载、替换和删除。新商品先保存基础资料，再继续上传素材。素材确认后立即保存，后续保存其他字段保留最新素材和 revision。重复确认同一图片不会重复加入图集。

负责人上传使用 `/api/supplier-catalog/sources/{source_id}/uploads`、`/confirm` 和 `/abort`，复用管理员上传的内容摘要、字节数、文件类型、票据主体与来源前缀校验，不获得管理员接口权限。图集为空时无法发布；已发布规格需要先停用才能清空最后一张图片。

浏览器直传要求素材桶 CORS 包含实际站点 origin、GET/HEAD/PUT、`Content-Type`、`If-None-Match`、`x-amz-checksum-sha256`，并暴露 `ETag`。本地测试桶已在保留 1420 端口配置的基础上添加 `http://localhost`。原始访问密钥继续仅在服务端使用。
